Назначение системы

SENTINEL Command Center — программный комплекс для централизованного мониторинга технических средств охраны, контроля за состоянием периметра и оперативного реагирования на инциденты безопасности. Система предназначена для развёртывания на охраняемых объектах с разнородным парком оборудования.

Функциональные возможности

  • Отображение устройств на интерактивной карте с цветовой индикацией статуса (онлайн / тревога / ТО / патруль / оффлайн)
  • Круги зон обнаружения/подавления вокруг устройств с анимацией при активном режиме
  • Группировка устройств по категориям и подсистемам (вкладки: СКУД, пожарная безопасность, моторизованные объекты и др.)
  • Панель детальной информации по каждому устройству с историей метрик
  • Бегущая лента событий с классификацией по критичности
  • Работа в тёмном и светлом режиме интерфейса
  • Поддержка оффлайн-карт (без доступа к интернету на объекте)
  • Загрузка произвольных иконок для устройств и категорий
  • Готовый WebSocket-интерфейс для подключения источников данных реального времени

Технологический стек

BACK
Python 3.13 + FastAPI
Основной сервер приложения. Асинхронная обработка HTTP-запросов и WebSocket-соединений. Автоматическая генерация OpenAPI документации.
ASGI
Uvicorn
Высокопроизводительный ASGI-сервер на базе uvloop. Обслуживает HTTP и WebSocket соединения одновременно.
БД
PostgreSQL 16 (портативный)
Реляционная СУБД. Поддержка JSONB-полей для гибких метрик. Запускается локально вместе с приложением.
ORM
asyncpg
Нативный асинхронный драйвер PostgreSQL для Python. Пул соединений, автоматическая сериализация JSONB, параметризованные запросы.
FRONT
Vanilla JS (ES2022)
Клиентская часть без фреймворков. Собственная реализация реактивного хранилища данных (Store) на паттерне pub/sub.
КАРТА
Leaflet.js 1.9
Интерактивная картографическая библиотека. Поддержка оффлайн-тайлов, SVG-слоёв, кастомных маркеров и анимированных кругов.
INFRA
Портативный PostgreSQL
Локальный PostgreSQL. Автоматический запуск, хранение данных в pgdata и резервное копирование через pg_dump.
TILES
CartoDB / ESRI (оффлайн)
Тайловые карты, закачанные локально. Тёмная схема (CartoDB Dark Matter) + спутниковые снимки (ESRI World Imagery). Работают без интернета.

Клиентская архитектура (Frontend)

Фронтенд построен без фреймворков на паттерне реактивного хранилища. Все модули общаются через единый объект Store:

Store.set('devices', data) → все компоненты, подписанные через Store.on('devices', handler), получают обновление одновременно. Карта перерисовывает маркеры, боковая панель обновляет список, бегущая строка перестраивает ленту — без прямых зависимостей между модулями.

Жизненный цикл сервера (Lifespan)

# При старте сервера (main.py):
1. run_migrations()   → применяет DDL (CREATE TABLE IF NOT EXISTS)
2. create_pool()      → asyncpg pool: 2–10 соединений к PostgreSQL
3. run_seed()         → начальные данные (только если devices = 0)
# При остановке:
4. close_pool()       → graceful shutdown всех соединений

API — интерфейс взаимодействия

Все эндпоинты отдают JSON. Базовый URL: http://<host>:8000. Документация OpenAPI доступна по адресу /docs.

Устройства /api/devices

GET
/api/devices
Список всех устройств с текущим состоянием, позицией, зонами обнаружения
GET
/api/devices/{id}
Детальная карточка устройства + последние 10 значений каждой метрики
POST
/api/devices/{id}/icon
Загрузка иконки устройства (multipart/form-data, PNG/JPG/SVG/WebP)

Инциденты /api/incidents

GET
/api/incidents?status=open&severity=critical&limit=50
Список инцидентов с фильтрацией по статусу и критичности
PATCH
/api/incidents/{uuid}
Обновление статуса инцидента (acknowledged, resolved, false_alarm...)

Зоны и статистика /api/zones

GET
/api/zones
Список зон с количеством устройств в каждой
GET
/api/zones/stats
Сводная статистика: онлайн/оффлайн/тревога/ТО + активные инциденты

Категории /api/categories

GET
/api/categories
Список категорий устройств
POST
/api/categories/{id}/icon
Загрузка иконки категории

WebSocket /ws

Эндпоинт ws://host:8000/ws готов для приёма и рассылки событий реального времени. Инфраструктура соединения реализована; требует подключения источника данных (интеграция с внешними системами).

Направления развития

Интеграция с оборудованием

  • REST/SOAP API внешних систем
  • ONVIF (IP-камеры)
  • MQTT (IoT-датчики)
  • RS-232/RS-485 (legacy оборудование)
  • GPS-трекеры (HTTP push)

Безопасность

  • JWT-авторизация операторов
  • Ролевая модель (оператор / старший / администратор)
  • Audit log всех действий
  • HTTPS / TLS

Аналитика

  • Дашборды по метрикам (графики временных рядов)
  • Отчёты по инцидентам
  • Тепловые карты активности
  • Экспорт в PDF / Excel

Масштабирование

  • Развёртывание на выделенном сервере
  • Репликация PostgreSQL
  • Резервное копирование БД
  • Мобильный клиент (планшет)
Текущие ограничения: система работает с демонстрационными данными. Реальные данные устройств поступают через API-интеграцию, которая реализуется на следующем этапе. WebSocket-канал для push-обновлений готов к подключению источника данных.
