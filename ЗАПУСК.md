# SENTINEL · ISSKB — Инструкция по запуску

Интеграционная платформа с веб-дашбордом. База данных (PostgreSQL) **встроена** и
поднимается сама вместе с программой — **Docker и отдельная установка СУБД не нужны**.

---

## Быстрый старт (3 шага)

1. **Установите Python 3.12 (x64)** — https://www.python.org/downloads/windows/
   При установке обязательно отметьте галочку **«Add Python to PATH»**.
2. Дважды кликните **`ЗАПУСТИТЬ.bat`**.
   *При самом первом запуске* скрипт скачает портативный PostgreSQL (нужен интернет,
   ~1 раз) и установит Python-зависимости. Это занимает несколько минут.
3. Откроется браузер на **http://localhost:8001**. Войдите:

   | Логин | Пароль |
   |-------|--------|
   | `admin` | `Admin123!` |

> ⚠️ После первого входа **смените пароль администратора** (см. «Безопасность»).

---

## Что происходит при запуске

`ЗАПУСТИТЬ.bat` → `start.ps1` выполняет три шага:

1. **PostgreSQL (портативный).** Проверяет папку `security_dashboard\pgsql\`.
   Если её нет — запускает `setup_postgres.ps1` (скачивание бинарников).
   Сам сервер БД поднимается уже внутри приложения (модуль `database/embedded_pg.py`):
   при первом старте создаётся кластер `pgdata\`, роль `sentinel_user` и базы
   `sentinel_isskb` / `sentinel_auth`. Порт БД — **5440**.
2. **Python и зависимости.** Находит рабочий Python, при необходимости ставит
   библиотеки (офлайн из `security_dashboard\wheels\` для Python 3.12, иначе через pip).
3. **Сервер.** Запускает `main.py` на порту **8001** и показывает адреса для входа.

Остановить сервер — **Ctrl + C** в окне (или просто закрыть окно). Встроенный
PostgreSQL при этом корректно гасится.

---

## Требования

- **Windows 10/11 (x64).**
- **Python 3.12 (x64)** — рекомендуется: библиотеки лежат заранее скачанными в
  `security_dashboard\wheels\` и ставятся **без интернета**. На других версиях
  (3.11 / 3.13) зависимости доустанавливаются из интернета через pip.
- **Интернет** нужен только один раз — при первой установке портативного PostgreSQL.
  Дальше система работает полностью автономно.

## Доступ с других компьютеров в локальной сети

Чтобы коллеги заходили на дашборд со своих ПК:

1. На этом ПК один раз запустите **`ОТКРЫТЬ_ДОСТУП_ПО_СЕТИ.bat`**
   (скрипт сам запросит права администратора). Он откроет порт **8001** в брандмауэре.
2. Узнайте IP этого ПК: в PowerShell выполните `ipconfig` и возьмите IPv4-адрес
   активного адаптера (Wi-Fi/Ethernet). Игнорируйте адреса `172.x`, `169.254.x`, VPN.
3. Профиль активной сети должен быть **«Частная»** (Private), не «Общедоступная».
   Проверка: `Get-NetConnectionProfile`.
4. Коллеги в той же сети открывают в браузере `http://<IP-этого-ПК>:8001`.

> Наружу открывается **только порт 8001** (веб-дашборд). Сам сервер уже слушает все
> интерфейсы (`0.0.0.0:8001`) — код менять не нужно.
>
> Если другому устройству нужен **прямой доступ к базе** (порт 5440) — см.
> `POSTGRES_SETUP.md`, раздел «Доступ по сети».

## Резервная копия и перенос на другой ПК

- **`СОХРАНИТЬ_БД.bat`** — выгружает обе базы в папку `dumps\`.
- **`ВОССТАНОВИТЬ_БД.bat`** — заливает базы обратно из `dumps\`.

**Перенос на новый ПК:** скопируйте всю папку проекта **вместе с `dumps\`**
(и с `security_dashboard\wheels\` для офлайн-установки). На новом ПК:
`ВОССТАНОВИТЬ_БД.bat` → затем `ЗАПУСТИТЬ.bat`.
Если переносить данные не нужно — базы создадутся пустыми (кроме учётки `admin`).

## Безопасность (важно — это система безопасности)

1. **Смените пароль `admin`** после первого входа — через панель `/admin`.
2. **Задайте постоянный секрет JWT**, иначе все сессии сбрасываются при каждом
   перезапуске сервера. В PowerShell (на этом ПК, один раз):
   ```powershell
   [Environment]::SetEnvironmentVariable('AUTH_JWT_SECRET', '<длинная-случайная-строка>', 'User')
   ```
   После этого перезапустите сервер.
3. **Пароль сетевого доступа к БД** (`sentinel123`) при желании смените через
   переменную `SENTINEL_PG_PASSWORD` (см. `POSTGRES_SETUP.md`). Локально приложение
   ходит в БД без пароля (trust), пароль нужен только для подключений по сети.
4. Не публикуйте порт 8001 в интернет — только доверенная локальная сеть или VPN.

## Расширенный режим: внешний PostgreSQL

Если нужно использовать **уже установленный** PostgreSQL вместо встроенного —
запускайте **`ЗАПУСТИТЬ_VM.bat`** (скрипт `start_vm.ps1`). Он подключается к
PostgreSQL на `127.0.0.1:5432` под `sentinel_user` / `sentinel123` и при
необходимости создаёт обе базы. Встроенный PostgreSQL в этом режиме не поднимается
(`SENTINEL_PG_EMBEDDED=0`).

## Диагностика

**Двойной клик по `.bat` ничего не делает / окно мелькает и закрывается.**
Убедитесь, что запускаете `.bat`, а не `.ps1` (у `.ps1` двойной клик открывает
Блокнот). Запускайте именно `ЗАПУСТИТЬ.bat`.

**«Нет соединения с сервером» на странице входа.**
Сервер ещё поднимается (при первом запуске — установка PostgreSQL и зависимостей).
Дождитесь в окне строки `Uvicorn running on http://0.0.0.0:8001` и обновите страницу.

**Порт 8001 занят.**
```powershell
Get-NetTCPConnection -LocalPort 8001
```
Закройте занявший процесс или смените порт в `security_dashboard\main.py`.

**PostgreSQL не установился (нет интернета при первом запуске).**
Запустите вручную при наличии сети:
```powershell
powershell -ExecutionPolicy Bypass -File security_dashboard\setup_postgres.ps1
```

**Python не найден / ставится «заглушка» из Microsoft Store.**
Установите Python 3.12 с python.org (галочка «Add to PATH») и отключите заглушку:
Параметры → Приложения → Псевдонимы выполнения приложений → выключить `python.exe`.

**Полный сброс данных (пересев с нуля):**
```powershell
cd security_dashboard
$env:PYTHONUTF8="1"
py -3.12 clear_db.py
```
При следующем запуске данные создадутся заново.
