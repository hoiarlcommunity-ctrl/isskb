# SENTINEL · ISSKB — Запуск на новом ПК (проверенная инструкция)

Пошаговый, **проверенный** порядок развёртывания дашборда на чистом компьютере.
Отличается от `РАЗВЁРТЫВАНИЕ_НА_ДРУГОМ_ПК.md` тем, что параметры БД здесь **точно
совпадают с настройками в коде** — приложение подключается без правок и без
переменных окружения.

> ⚠️ **Главное отличие от старых скриптов.** Код по умолчанию ждёт PostgreSQL на
> **порту 5440** и подключается **без пароля** (`database/connection.py` →
> `SENTINEL_DSN`, `auth/config.py` → `AUTH_DSN`). А `start.ps1` /
> `ВОССТАНОВИТЬ_БД.bat` создают контейнер на **5432 с паролем** — это **не совпадает**
> с кодом, и на чистом ПК сервер не достучится до своей базы. Ниже — контейнер на
> **5440 + trust**, как в коде. Бонус: порт 5432 не используется вообще, поэтому
> любой уже стоящий на ПК PostgreSQL **не мешает** — конфликта нет.

---

## 0. Архитектура (коротко)

| Компонент | Что | Где |
|-----------|-----|-----|
| Веб-сервер | FastAPI + Uvicorn | Хост-ПК, порт **8001** |
| СУБД | PostgreSQL 16 (Docker) | контейнер `sentinel-postgres`, хост-порт **5440** → 5432 |
| БД `sentinel_isskb` | устройства, инциденты, зоны | в контейнере |
| БД `sentinel_auth` | пользователи, сессии, аудит | в контейнере |

Схема: браузер → `http://<IP>:8001` → Uvicorn → пул asyncpg → PostgreSQL (5440).
Наружу открывается **только 8001**. База в сеть не публикуется.

## 1. Что установить (один раз)

1. **Windows 10/11 x64.**
2. **Docker Desktop** — https://www.docker.com/products/docker-desktop/
   - Включить бэкенд **WSL 2** (установщик предложит).
   - Запустить хотя бы раз, дождаться статуса **«Docker Desktop is running»**.
3. **Python 3.12 (x64)** — https://www.python.org/downloads/windows/
   - Нужна **именно 3.12**: библиотеки лежат заранее скачанными в
     `security_dashboard\wheels\` и собраны под **Python 3.12 / Windows x64**
     (напр. `asyncpg-…-cp312-…win_amd64.whl`). На 3.11/3.13 офлайн-установка не сойдётся.
   - **Обязательно** отметить **«Add Python to PATH»**.
   - Проверка: `python --version` → `Python 3.12.x`.

Проверка окружения (PowerShell):
```powershell
docker --version
docker info          # без ошибок = Docker запущен
python --version     # Python 3.12.x
```

## 2. Перенести файлы проекта

Скопировать папку `ISSKB\` на новый ПК (любой диск).

**Обязательно должно быть:**
- `security_dashboard\` — весь код (`main.py`, `api\`, `auth\`, `database\`,
  `services\`, `websocket\`, `static\`, `config\`, `requirements.txt`);
- `security_dashboard\wheels\` — **офлайн-библиотеки** (~34 `.whl`). Без неё установка без интернета не сработает;
- `dumps\` — **если переносите данные** (см. шаг 4).

**Можно НЕ копировать** (пересоздастся):
- `security_dashboard\.venv\` — часто «сломано» (указывает на несуществующий Python). Создадите заново;
- `__pycache__\`, `*.pyc`, `security_dashboard\tiles\` (кэш карт).

## 3. Поднять базу данных (Docker) — рецепт под код

Запустите **Docker Desktop**. Затем в **PowerShell** выполните (одним блоком):

```powershell
docker run -d `
  --name sentinel-postgres `
  -e POSTGRES_USER=sentinel_user `
  -e POSTGRES_DB=sentinel `
  -e POSTGRES_HOST_AUTH_METHOD=trust `
  -p 5440:5432 `
  -v sentinel-pgdata:/var/lib/postgresql/data `
  --restart unless-stopped `
  postgres:16-alpine
```

Ключевое:
- `-p 5440:5432` — хост-порт **5440**, как ждёт код (и не трогает чужой PostgreSQL на 5432);
- `POSTGRES_HOST_AUTH_METHOD=trust` — вход **без пароля**, как в DSN кода;
- `--restart unless-stopped` — контейнер сам поднимется после перезагрузки.

Дождитесь готовности и **создайте обе базы** (приложение создаёт таблицы, но не сами базы):

```powershell
docker exec sentinel-postgres pg_isready -U sentinel_user      # должно быть "accepting connections"
docker exec sentinel-postgres psql -U sentinel_user -d sentinel -c "CREATE DATABASE sentinel_isskb OWNER sentinel_user;"
docker exec sentinel-postgres psql -U sentinel_user -d sentinel -c "CREATE DATABASE sentinel_auth  OWNER sentinel_user;"
```

Проверка (обе базы должны быть в списке):
```powershell
docker exec sentinel-postgres psql -U sentinel_user -d sentinel -tAc "SELECT datname FROM pg_database WHERE datname LIKE 'sentinel%';"
```

## 4. (Опционально) Восстановить данные из дампов

Если нужны существующие данные, а не пустые базы. **На старом ПК** сначала
`СОХРАНИТЬ_БД.bat` (обновит `dumps\`). Затем на новом ПК, из корня проекта (cmd):

```bat
type dumps\sentinel_isskb.sql | docker exec -i sentinel-postgres psql -U sentinel_user -d sentinel_isskb -q
type dumps\sentinel_auth.sql  | docker exec -i sentinel-postgres psql -U sentinel_user -d sentinel_auth  -q
```

> Не используйте `ВОССТАНОВИТЬ_БД.bat` как есть — он делает контейнер на **5432 с паролем**
> (не совпадает с кодом). Заливайте дампы в контейнер из шага 3 командами выше.
> Без восстановления базы создаются пустыми — в `sentinel_auth` появится только
> учётка `admin` / `Admin123!`.

## 6. Запуск сервера

```powershell
cd <путь>\security_dashboard
# постоянный секрет JWT — иначе все сессии сбрасываются при каждом перезапуске:
$env:AUTH_JWT_SECRET = "замените-на-длинную-случайную-строку"
$env:PYTHONUTF8 = "1"     # обязательно: иначе кириллица в консоли валит сервер (cp1252)
python main.py
```

Признак успеха в консоли:
```
[DB] Schema applied (PostgreSQL)
INFO:  Application startup complete.
INFO:  Uvicorn running on http://0.0.0.0:8001
```
Браузер откроется сам на `http://127.0.0.1:8001`. Остановка сервера — **Ctrl + C**
(контейнер БД продолжит работать).

### Чтобы секрет JWT сохранялся между сеансами (задать один раз)
```powershell
[Environment]::SetEnvironmentVariable('AUTH_JWT_SECRET', '<длинная-случайная-строка>', 'User')
```
(после этого перезапустить сервер; `$env:...` в шаге 6 больше не нужен).

## 7. Первый вход и безопасность

Учётка администратора по умолчанию (создаётся при первом создании `sentinel_auth`):

| Логин | Пароль |
|-------|--------|
| `admin` | `Admin123!` |

**Сразу после первого входа:**
1. Смените пароль `admin` — панель `http://localhost:8001/admin` → профиль.
2. Убедитесь, что задан `AUTH_JWT_SECRET` (шаг 6).
3. Пользователей коллегам создавайте через `/admin` (роли: `admin` / `operator` / `viewer`).

## 8. Всплывающее окно «Server disconnected without sending a response»

Это **не ошибка запуска**, а сигнал модуля heartbeat: сервер каждые 30 с опрашивает
внешний сервер данных из `config/settings.json`. Если этого сервера в вашей сети нет
(автономный/демо-режим) — оставьте источник **отключённым**:

```json
// config/settings.json → ext_sources[0]
"is_active": false
```
При `is_active:false` мониторинг «спит», окно не появляется. Чтобы **включить** реальный
внешний сервер: `is_active:true` и укажите достижимый `base_url`. Файл сохранять в **UTF-8**
(иначе кириллица превратится в `???`).

## 9. (Опционально) Доступ по локальной сети

Сервер уже слушает `0.0.0.0:8001` — код менять не нужно. Кратко:
1. `ОТКРЫТЬ_ДОСТУП_ПО_СЕТИ.bat` — от администратора, один раз (правило брандмауэра TCP 8001).
2. `ipconfig` → взять IPv4 активного адаптера (игнорировать `172.x`, `169.254.x`, VPN).
3. `Get-NetConnectionProfile` → профиль сети должен быть **Private**, не Public.
4. Коллеги в той же подсети: `http://<IP-хоста>:8001`.

Подробности и разбор проблем сети — в `РАЗВЁРТЫВАНИЕ_НА_ДРУГОМ_ПК.md`, разделы 4 и 7.4.

## 11. Диагностика

**Сервер падает при старте / `asyncpg … Connection…Error`.**
Почти всегда — БД недоступна по адресу из кода. Проверьте:
```powershell
docker ps                                            # sentinel-postgres должен быть Up, порт 0.0.0.0:5440->5432
docker exec sentinel-postgres pg_isready -U sentinel_user
```
Быстрая проверка соединения ровно как у приложения (порт 5440, без пароля):
```powershell
python -c "import asyncio,asyncpg; asyncio.run(asyncpg.connect('postgresql://sentinel_user@127.0.0.1:5440/sentinel_isskb')); print('DB OK')"
```
Если ошибка про пароль (`InvalidPasswordError`) — контейнер создан **не** с
`POSTGRES_HOST_AUTH_METHOD=trust` (например старым скриптом на 5432). Пересоздайте
контейнер по шагу 3, либо задайте DSN с паролем через переменные среды:
```powershell
$env:SENTINEL_DSN = "postgresql://sentinel_user:sentinel123@127.0.0.1:5440/sentinel_isskb"
$env:AUTH_DSN     = "postgresql://sentinel_user:sentinel123@127.0.0.1:5440/sentinel_auth"
```

**`ModuleNotFoundError` (psutil / bcrypt / jose / httpx).** Зависимости не поставлены —
повторите шаг 5 (активируйте `.venv` перед `python main.py`).

**`UnicodeEncodeError … charmap`.** Не задан `PYTHONUTF8=1` — см. шаг 6.

**Порт 8001 занят.** `Get-NetTCPConnection -LocalPort 8001` → закрыть процесс либо
сменить порт в `main.py` (`uvicorn.run(... port=8001 ...)`).

**Пересоздать БД начисто** (удалит все данные!):
```powershell
docker rm -f sentinel-postgres
docker volume rm sentinel-pgdata
```
Затем шаг 3 заново.
