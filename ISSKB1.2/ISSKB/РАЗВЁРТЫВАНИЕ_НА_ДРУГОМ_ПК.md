# Развёртывание SENTINEL ISSKB на другом ПК и доступ по локальной сети

Полная пошаговая инструкция: как поднять систему на новом компьютере и открыть
к ней доступ так, чтобы коллеги из той же локальной сети могли заходить в браузере.

---

## 0. Как устроена система (коротко)

| Компонент | Что это | Где работает |
|-----------|---------|--------------|
| **Веб-сервер** | FastAPI + Uvicorn (Python), сам дашборд и API | Хост-ПК, порт **8001** |
| **СУБД** | PostgreSQL 16 | Docker-контейнер `sentinel-postgres`, порт **5432** |
| **База `sentinel_isskb`** | Основные данные (устройства, инциденты, зоны…) | В контейнере |
| **База `sentinel_auth`** | Учётные записи, сессии, аудит входов | В контейнере |

Схема доступа: браузер коллеги → `http://<IP-хоста>:8001` → Uvicorn → пул asyncpg →
PostgreSQL в Docker. Наружу (в сеть) открывается **только порт 8001**. База данных
в сеть не публикуется.

> Сервер уже настроен слушать все интерфейсы (`0.0.0.0:8001`), поэтому для доступа из
> сети нужно лишь открыть порт в брандмауэре — код менять не требуется.

## 1. Что установить на новом ПК (предварительные требования)

1. **Windows 10/11** (64-bit).
2. **Docker Desktop** — https://www.docker.com/products/docker-desktop/
   - При установке включить бэкенд **WSL 2** (Docker сам предложит поставить WSL).
   - После установки запустить Docker Desktop хотя бы один раз и дождаться статуса
     «Docker Desktop is running».
3. **Python 3.12 (x64)** — https://www.python.org/downloads/windows/
   - Нужна именно версия **3.12**: библиотеки поставляются **заранее скачанными**
     (папка `security_dashboard\wheels\`) и собраны под Python 3.12 / Windows x64.
   - **ОБЯЗАТЕЛЬНО** отметить галочку **«Add Python to PATH»** в установщике.
   - Проверка: `python --version` → `Python 3.12.x`.
   - (Если нужен другой Python/ОС — пересоберите папку wheels, см. раздел 7.2.)

> **Важно:** все Python-библиотеки уже лежат в `security_dashboard\wheels\` и
> устанавливаются **офлайн, без интернета**. При запуске скрипт НЕ обращается к PyPI.
> Интернет нужен только для скачивания Docker Desktop и Python (пункты 2–3).

Проверка, что всё на месте (PowerShell):
```powershell
docker --version
python --version
docker info        # должен отработать без ошибок = Docker запущен
```

## 3. Первый запуск

1. Запустите **Docker Desktop**, дождитесь «running».
2. В папке проекта дважды кликните **`ЗАПУСТИТЬ.bat`**.

Скрипт `start.ps1` автоматически выполнит 5 шагов:
1. Проверит/запустит Docker Desktop.
2. Создаст (при первом запуске) и запустит контейнер `sentinel-postgres`
   (пользователь `sentinel_user`, пароль `sentinel123`, порт `5432`,
   данные — в Docker-томе `sentinel-pgdata`).
3. Дождётся готовности PostgreSQL.
4. Создаст **обе** базы: `sentinel_isskb` и `sentinel_auth` (если их нет).
5. Установит Python-зависимости **офлайн** из папки `security_dashboard\wheels\`
   (без обращения к интернету) и запустит сервер. Если библиотеки уже
   установлены — этот шаг просто пропускается.

После этого в консоли появятся адреса:
```
   Этот ПК:          http://localhost:8001
   Из локальной сети: http://<IP-этого-ПК>:8001
```

### Первый вход (учётка администратора по умолчанию)
При первом создании базы `sentinel_auth` автоматически создаётся администратор:

| Логин | Пароль |
|-------|--------|
| `admin` | `Admin123!` |

> **Сразу смените пароль администратора** после первого входа (см. раздел 5, безопасность).

## 4. Доступ по локальной сети (главное)

Чтобы коллеги заходили со своих ПК:

### Шаг 4.1 — открыть порт 8001 в брандмауэре
На хост-ПК запустите **`ОТКРЫТЬ_ДОСТУП_ПО_СЕТИ.bat`** (правый клик → «Запуск от
имени администратора», либо просто двойной клик — скрипт сам запросит UAC).

Он создаёт разрешающее входящее правило для `TCP 8001` (профили «Частная» и
«Доменная») и покажет адрес для подключения. Запускать нужно **один раз**.

### Шаг 4.2 — узнать IP хост-ПК
В PowerShell:
```powershell
ipconfig
```
Возьмите **IPv4-адрес** активного сетевого адаптера (Wi-Fi или Ethernet).
Пример: `10.50.228.206`.

> Игнорируйте адреса виртуальных адаптеров: `172.x` (WSL/Hyper-V/Docker),
> `169.254.x` (нет сети), а также адреса VPN-туннелей.

### Шаг 4.3 — проверить профиль сети (важно!)
Правило открыто для профилей «Частная»/«Доменная». Если активная сеть помечена
как **«Общедоступная» (Public)** — доступа не будет. Проверка/смена:
```powershell
Get-NetConnectionProfile                       # смотрим NetworkCategory
# сменить на Частную (от администратора):
Set-NetConnectionProfile -InterfaceAlias 'Беспроводная сеть' -NetworkCategory Private
```
(имя адаптера подставьте своё из вывода `Get-NetConnectionProfile`)

### Шаг 4.4 — коллеги заходят
На любом ПК в **той же локальной сети** открыть в браузере:
```
http://<IP-хоста>:8001
```
например `http://10.50.228.206:8001`, и войти со своим логином/паролем
(учётки создаёт администратор — раздел 5).

### Условия, чтобы «видели» друг друга
- Хост-ПК и клиенты — в **одной сети / подсети** (одинаковые первые 3 октета IP при
  маске `/24`, напр. `10.50.228.x`).
- Сервер на хосте **запущен** (окно `ЗАПУСТИТЬ.bat` открыто).
- Ничто не блокирует: брандмауэр (шаг 4.1), сторонний антивирус, изоляция клиентов
  на роутере («AP/Client isolation» — выключить в настройках Wi-Fi).
- На клиентах не должен мешать VPN, уводящий трафик мимо локальной сети.

> **Совет:** IP по DHCP может меняться после перезагрузки роутера. Чтобы адрес был
> постоянным — зарезервируйте IP за MAC-адресом хоста в настройках роутера или
> задайте статический IP в свойствах адаптера. Тогда ссылка `http://<IP>:8001` не
> «съедет».

## 5. Создание пользователей для коллег

### Способ 1 — через панель администратора (рекомендуется)
1. Войдите как `admin`.
2. Откройте `http://localhost:8001/admin`.
3. Создайте пользователей. Роли:
   - **admin** — полный доступ + панель администрирования;
   - **operator** — рабочий доступ (свой офис);
   - **viewer** — только просмотр.

### Способ 2 — программно (через API)
Логин админа → `POST /api/admin/users`. Пример на PowerShell:
```powershell
# 1) вход админом (сохраняем cookie-сессию)
$body = @{ username='admin'; password='Admin123!' } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8001/auth/login -Method Post `
    -ContentType 'application/json' -Body $body -SessionVariable S | Out-Null

# 2) создание пользователя
$u = @{ username='ivanov'; password='Пароль_минимум_6'; role='operator'; office_id='main' } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8001/api/admin/users -Method Post `
    -ContentType 'application/json' -Body $u -WebSession $S
```
> **Важно:** не создавайте пользователей командами через «сырой» shell со
> спец-символами в пароле в кавычках — пароль может исказиться при передаче.
> Используйте панель `/admin` или `ConvertTo-Json`/`Invoke-RestMethod` как выше
> (JSON-кодирование гарантирует, что сохранится ровно тот пароль, что вы задали).

Требования к полям: логин ≥ 3 символа, пароль ≥ 6 символов.

## 6. Перенос данных БД на новый ПК (если нужно)

По умолчанию на новом ПК базы создаются **пустыми** (кроме учётки `admin`).
Чтобы перенести существующие данные:

### На исходном ПК — сделать дампы
Запустите **`СОХРАНИТЬ_БД.bat`**. Он выгрузит обе базы в
`dumps\sentinel_isskb.sql` и `dumps\sentinel_auth.sql`.

### Перенести
Скопируйте папку проекта **вместе с `dumps\`** на новый ПК.

### На новом ПК — восстановить
1. Запустите Docker Desktop.
2. Запустите **`ВОССТАНОВИТЬ_БД.bat`** — он создаст контейнер (если нужно), обе базы
   и зальёт данные из `dumps\*.sql`.
3. Затем `ЗАПУСТИТЬ.bat`.

> Дампы в репозитории (`dumps\`) могут быть устаревшими — перед переносом
> пересоздайте их через `СОХРАНИТЬ_БД.bat`.

## 7. Диагностика типовых проблем

### 7.1 Ошибка `asyncpg ... ConnectionDoesNotExistError` / сервер падает при старте
**Причина №1 (частая): порт 5432 занят другим PostgreSQL.**
Если на ПК стоит **нативный PostgreSQL** (служба `postgresql-x64-XX`), он занимает
порт 5432 раньше Docker, и приложение подключается не к контейнеру, а к чужому
серверу (где нет роли `sentinel_user`).

Диагностика (PowerShell):
```powershell
Get-NetTCPConnection -LocalPort 5432 -State Listen |
  ForEach-Object { (Get-Process -Id $_.OwningProcess).ProcessName }
```
- `com.docker.backend` → порт за Docker, всё правильно.
- `postgres` → порт занял **нативный** PostgreSQL, надо освободить.

Решение (PowerShell **от администратора**):
```powershell
Stop-Service postgresql-x64-18                     # номер версии свой
Set-Service  postgresql-x64-18 -StartupType Manual # чтобы не занимал порт после перезагрузки
docker restart sentinel-postgres                    # Docker займёт 5432
```
(Вернуть нативный PostgreSQL при необходимости:
`Set-Service postgresql-x64-18 -StartupType Automatic; Start-Service postgresql-x64-18`.)

### 7.2 `ModuleNotFoundError` (например `psutil`, `bcrypt`, `jose`, `httpx`)
Не установлены зависимости. Установите вручную **офлайн** (из папки `wheels\`, без интернета):
```powershell
cd <папка>\security_dashboard
python -m pip install --no-index --find-links wheels -r requirements.txt
```
Если появляется ошибка вида «No matching distribution» — значит колёса в `wheels\`
не подходят к вашему Python/ОС (папка собрана под **Python 3.12 / Windows x64**). Варианты:
- поставить именно **Python 3.12 x64** (проще всего);
- либо **пересобрать** папку wheels на машине с нужным Python и той же ОС
  (единственная команда, где нужен интернет, и только один раз):
  ```powershell
  cd <папка>\security_dashboard
  python -m pip download -r requirements.txt -d wheels --only-binary :all:
  ```

### 7.3 `Could not open requirements file: 'requiremens.txt'`
Опечатка в команде (`requiremens` вместо `requirements`). Правильный файл —
`security_dashboard\requirements.txt`. Запускайте `ЗАПУСТИТЬ.bat`, а не ручную
команду с опечаткой.

### 7.4 Коллеги не могут открыть `http://<IP>:8001`
Проверьте по порядку:
1. Сервер запущен на хосте (окно `ЗАПУСТИТЬ.bat` открыто).
2. Правило брандмауэра создано (`ОТКРЫТЬ_ДОСТУП_ПО_СЕТИ.bat`).
3. Профиль активной сети = «Частная» (раздел 4.3), а не «Общедоступная».
4. Правильный IP хоста (раздел 4.2), клиент в той же подсети.
5. На роутере выключена изоляция клиентов (AP isolation).
6. Быстрая проверка с клиента: `ping <IP-хоста>` и в браузере `http://<IP>:8001`.
7. Проверка порта с клиента (PowerShell): `Test-NetConnection <IP-хоста> -Port 8001`
   — поле `TcpTestSucceeded : True` означает, что порт доступен.

### 7.5 Порт 8001 уже занят
Найдите процесс: `Get-NetTCPConnection -LocalPort 8001`. Либо закройте его, либо
смените порт сервера в `security_dashboard\main.py` (строка `uvicorn.run(... port=8001 ...)`)
и в правиле брандмауэра.

### 7.6 Docker не стартует / контейнер не создаётся
Убедитесь, что включён WSL 2 и виртуализация в BIOS. Перезапустите Docker Desktop.

## 8. Управление сервером

- **Запуск:** `ЗАПУСТИТЬ.bat`
- **Остановка сервера:** `Ctrl + C` в окне сервера (контейнер БД продолжит работать).
- **Остановить БД:** `docker stop sentinel-postgres` · **запустить:** `docker start sentinel-postgres`
- **Логи БД:** `docker logs sentinel-postgres`
- **Автозапуск БД** уже настроен (`--restart unless-stopped`) — контейнер сам
  поднимется после перезагрузки, когда запустится Docker Desktop.

## 9. Безопасность (важно — это система безопасности)

По умолчанию значения тестовые. Перед реальной эксплуатацией:

1. **Смените пароль `admin`** (через `/admin` → профиль, или reset-password).
2. **Задайте постоянный секрет JWT**, иначе все сессии сбрасываются при каждом
   перезапуске сервера. Задайте системную переменную среды на хосте:
   ```powershell
   [Environment]::SetEnvironmentVariable('AUTH_JWT_SECRET', '<длинная-случайная-строка>', 'User')
   ```
   (после этого перезапустить сервер).
3. **Пароль PostgreSQL** (`sentinel123`) при желании сменить — тогда обновите его в
   `security_dashboard\database\connection.py` (`DSN`) и `security_dashboard\auth\config.py`
   (`AUTH_DSN`), пересоздайте контейнер с новым `POSTGRES_PASSWORD`.
4. **Не публикуйте порт 8001 в интернет.** Доступ по HTTP (без шифрования) —
   только для доверенной локальной сети. Для выхода наружу используйте VPN или
   обратный прокси с HTTPS.
5. Правило брандмауэра намеренно **не** открыто для профиля «Общедоступная».
